4.1.1 - WeatherParse (unreleased)
=================================

Removed
-------

- Google Analytics and Matomo support: settings, page scripts and config template. The updater (4.1.0 -> 4.1.1) and
  any settings save delete the old keys from config.php. WeatherParse loads no tracking code.
- The Acuparse site icon and the social sharing photo (an AcuRite product photo with unclear license).

Added
-----

- Original WeatherParse artwork: site icon (favicon.ico 16/32/48, favicon.svg, apple-touch-icon.png) and a social
  card (img/social.png) used when no camera is set up. See docs/other/ARTWORK.txt.
- Weathercloud: optional Software ID setting for an ID that Weathercloud issues.

Changed
-------

- Weathercloud uploads send software=WeatherParse_v<version> and no longer send the software ID that Weathercloud
  issued to Acuparse. The upload log row is SQL escaped and a failed request is logged as "No response".

Fixed
-----

- Dashboard and API: when a table has no row yet (just after midnight, a new install or an offline sensor) the
  high/low temperature, peak wind and peak gust times are null instead of a 1969 date, and numbers are 0 without
  PHP warnings. A missing last update row counts as "no data received".
- Docker: the entrypoint no longer copies the MYSQL_ variables (root password included) into the world-readable
  /etc/environment. Cron jobs read a root-only /etc/weatherparse/cron.env (600) without the root password; the root
  password is removed from the environment after the startup permission check, so Apache/PHP never see it; database
  commands use MYSQL_PWD instead of -p on the command line; MYSQL_PASSWORD_FILE and MYSQL_ROOT_PASSWORD_FILE (Docker
  secrets) are supported; the admin config API hides password, secret, key and token environment values. The backup
  cron job now also receives the BACKUP_, KEEP_, NFS_ and SMB_ settings from the container environment.

4.1.0 - WeatherParse (unreleased)
=================================

Added
-----

- Low battery email alerts. The cron job checks the AcuRite Access hub (its backup batteries), the Atlas, the Iris and
  every tower, and emails when one reports a low battery, again at a reminder interval (default 24 hours) while it
  stays low, and once when it is normal again. One email lists every low device, when it went low and which batteries
  to replace, with links to the dashboard and the sensor status page. Devices that have not reported for an hour are
  skipped (that is an outage). Settings in Admin, Settings, Features: on/off, recipients (empty = all admins, like
  outage alerts), reminder hours (0 = none) and the battery OK email. State is kept in the new battery_alert table.
- Updater step 4.0.0 -> 4.1.0: adds the battery alert settings (on when Mailgun or a local mail program is set up)
  and creates the battery_alert table. Cron also creates the table if it is missing.
- Battery alerts wait an hour after a failed send before trying again (new battery_alert.last_attempt column), so a
  broken mail setup does not retry every minute.

Fixed
-----

- Mailgun mail no longer crashes the caller when Mailgun answers with plain text (for example "Forbidden" for a
  sandbox domain's unapproved recipient): the reply is always returned as an array and failures are logged with the
  HTTP status and Mailgun's message. This also affected outage alerts.
- Mailgun requests now verify Mailgun's TLS certificate (it was turned off) and time out after 30 seconds.
- The admin "Send Test Email" button reports failure when Mailgun did not accept the mail (it showed success).

4.0.0 - WeatherParse (unreleased)
=================================

WeatherParse is a fork of Acuparse 3.9.4 by Maxwell Power (AGPL-3.0). Entries below 4.0.0 are Acuparse history.

Changed
-------

- Renamed to WeatherParse: paths /opt/weatherparse, Apache sites config/weatherparse*.conf, syslog tag weatherparse,
  defaults for new installs (database, user, MQTT client and topic) weatherparse. Existing installs keep their values.
- Requires Debian 12 or 13 with PHP 8.2 to 8.4.
- Update check reads the public GitHub release list only (api.github.com/repos/mobilevoid/weatherparse/releases/latest).
- Windy uploads use the Windy Stations API v2 (station ID plus station password; metric units). API v1 is retired.
- MyAcuRite forwarding goes directly to AcuRite. The address is looked up in DNS (not /etc/hosts) so a local redirect
  cannot loop the data back, and the third-party acuparse.com relay option is gone.
- Backups (cron/backup) are incremental snapshots (hard links for unchanged files) to a local folder, an NFS export or
  an SMB share, with rotation (KEEP_SNAPSHOTS) and a daily, weekly or monthly schedule (backup install-cron). Settings
  in cron/backup.conf (template in cron/templates). Restore with backup restore [NAME].
- Documentation is plain text (.txt) with a manual install guide for Debian 12/13 and Raspberry Pi OS.

Added
-----

- Temperature spike filter: drops Iris/Atlas temperatures below -60 F, above 140 F, or changing more than a set limit
  (default 10 F per 5 minutes) from the last stored reading. Other readings in the report are kept.
- Maintenance mode: records locally but pauses every upload and MyAcuRite forwarding while the sensor is serviced.
- Second camera (CAMERA2_HOST in cam/config.env) with its own archive and names on the camera page.
- Camera image retention: KEEP_DAYS in cam/config.env, applied by a daily "webcam cleanup" cron job.
- Camera script lock so overlapping cron runs skip instead of clashing.

Removed
-------

- Telemetry: the daily report of OS, kernel, install ID and hub MAC to version.acuparse.com.
- Donation and sponsor links, the Acuparse GitLab CI, and the old documentation site files (including its analytics tag).

Fixed
-----

- PHP 8: deprecated FILTER_SANITIZE_STRING replaced (117 uses) with an identical helper; SQL errors no longer abort
  data processing; missing lightning distance stored as NULL; no rainfall row no longer warns.
- Settings: a field the browser does not send (a disabled service) keeps its saved value. Before, saving the settings
  page erased Weather Underground, CWOP and Mailgun credentials of any disabled service.
- Settings: Realtime UTC buttons were inverted, so every save flipped the setting.
- Settings: saving Windy settings overwrote the Windguru URL.
- The "Filter Erroneous Access Readings" setting never ran (it compared true with 1).
- Installer and maintenance scripts no longer put the database password on the command line, and use the configured
  database name instead of a hard-coded one.
- Camera: images were not published when MODE was 'local' on a single server (documented); a trailing slash on a page
  (for example /archive/) no longer returns a server error.
