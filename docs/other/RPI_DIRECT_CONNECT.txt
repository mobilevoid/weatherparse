WEATHERPARSE RASPBERRY PI DIRECT CONNECTION GUIDE
=================================================

This guide sets up WeatherParse on a Raspberry Pi with an AcuRite Access (or smartHUB) plugged directly into the Pi's
Ethernet port. The Pi joins your home network over Wi-Fi (or a USB Ethernet adapter) and runs a tiny private network
on its Ethernet port for the Access.

It is based on a community guide from the Acuparse project, updated for Raspberry Pi OS Lite based on Debian 12
(bookworm) and Debian 13 (trixie). If you are not connecting the Access directly to the Pi, follow docs/INSTALL.txt
only.

Parts List
==========

- Raspberry Pi 4 (a Pi 3 also works; a Pi Zero is not recommended: too slow and only one port)
- Official Raspberry Pi power supply
- Case (optional but recommended)
- MicroSD card, 32 GB or larger, a fast A1/A2 rated card. WeatherParse reads and writes a lot.
- Optional: USB Ethernet adapter, if you want a wired connection to your router instead of Wi-Fi
- An AcuRite Access (or smartHUB) and an Ethernet cable

Hardware Setup
==============

The Access connects to the Pi's built-in Ethernet port with a network cable. The Pi connects to your home network
over Wi-Fi (or a USB Ethernet adapter). The Pi runs "headless" (no monitor, keyboard, or mouse).

Installation
============

Install Raspberry Pi OS Lite
----------------------------

Use Raspberry Pi Imager to write Raspberry Pi OS Lite (64-bit) to the card. In the Imager settings set the hostname,
your user and password, your Wi-Fi network (and its country), and enable SSH. Boot the Pi and connect with SSH.

On Windows, the built-in ssh command (in Terminal or PowerShell) works; PuTTY is an alternative.

Network Names
-------------

Run:

    ip -br link

Debian 12 and later call the built-in Ethernet port end0 (older systems: eth0) and Wi-Fi wlan0. A USB Ethernet adapter
gets a name starting with enx followed by its MAC address. This guide uses end0 for the Access port and wlan0 for the
home network; use your own names.

Fixed Addresses
---------------

Raspberry Pi OS based on Debian 12 and 13 uses NetworkManager. Give the Pi a fixed address on your home network
(either a DHCP reservation in your router, or with nmcli) and give the Access port a fixed address with no gateway:

    sudo nmcli connection add type ethernet ifname end0 con-name access-link \
        ipv4.method manual ipv4.addresses 192.168.6.1/24 ipv4.never-default yes ipv6.method link-local

Turn off Wi-Fi power saving, which can make a Pi 4 silently drop off Wi-Fi. Create
/etc/NetworkManager/conf.d/wifi-powersave-off.conf containing:

    [connection]
    wifi.powersave = 2

dnsmasq for the Access
----------------------

    sudo apt update && sudo apt -y install dnsmasq iptables-persistent

During the iptables-persistent install you can answer No to saving the current rules.

Create /etc/dnsmasq.conf (keep a copy of the original first). It is also in config/dnsmasq-hub.conf.example.

    # Serve only the Access port; the Pi itself keeps using your normal DNS
    interface=end0
    except-interface=lo
    bind-interfaces
    no-dhcp-interface=wlan0
    dhcp-range=end0,192.168.6.50,192.168.6.100,255.255.255.0,24h
    # The Access gets the redirect; everything else goes to public DNS
    no-hosts
    no-resolv
    server=8.8.8.8
    server=1.1.1.1
    address=/atlasapi.myacurite.com/192.168.6.1

This is two resolvers: dnsmasq answers only the Access and points the AcuRite upload host at the Pi's address on
the Ethernet port (192.168.6.1). The Pi itself keeps using your router's DNS over Wi-Fi, so it sees AcuRite's real
address and can forward readings to MyAcuRite. Do not add atlasapi.myacurite.com to /etc/hosts.

Stop dnsmasq from becoming the Pi's own resolver:

    echo 'DNSMASQ_EXCEPT="lo"' | sudo tee -a /etc/default/dnsmasq
    sudo resolvconf -u

(For a smartHUB the host is hubapi.myacurite.com. AcuRite's smartHUB service no longer exists, so smartHUB readings
are stored but not forwarded to MyAcuRite.)

Routing and the DNS Redirect
----------------------------

Share the Pi's connection with the Access, and redirect the Access's DNS to the Pi. Current Access firmware ignores
the DNS server handed out by DHCP and asks 8.8.4.4 directly; without the redirect it sends its readings straight to
AcuRite.

    echo net.ipv4.ip_forward=1 | sudo tee /etc/sysctl.d/90-weatherparse.conf
    sudo sysctl --system
    sudo iptables -A FORWARD -i end0 -o wlan0 -s 192.168.6.0/24 -m conntrack --ctstate NEW -j ACCEPT
    sudo iptables -A FORWARD -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
    sudo iptables -t nat -A POSTROUTING -o wlan0 -j MASQUERADE
    sudo iptables -t nat -A PREROUTING -i end0 -s 192.168.6.0/24 -p udp --dport 53 -j DNAT --to-destination 192.168.6.1:53
    sudo iptables -t nat -A PREROUTING -i end0 -s 192.168.6.0/24 -p tcp --dport 53 -j DNAT --to-destination 192.168.6.1:53
    sudo netfilter-persistent save

If you use a wired USB adapter for your home network, replace wlan0 with its name.

Restart dnsmasq and power cycle the Access:

    sudo systemctl restart dnsmasq

If the Access keeps sending to AcuRite after the rules are in place, it is reusing an old DNS connection. Power cycle
it again, or clear its connections with: sudo conntrack -D -s <access ip> (package conntrack).

WeatherParse Installation
-------------------------

Follow the manual install in docs/INSTALL.txt. Then open http://<your Pi IP>/ in a browser to finish the setup.

Check It Works
==============

- The Access gets an address from the Pi: grep DHCPACK /var/log/syslog
- Readings arrive every 5 minutes: grep 192.168.6. /var/log/apache2/access.log
- To see exactly what the Access sends, capture its traffic: sudo tcpdump -nn -i end0 host <access ip>
