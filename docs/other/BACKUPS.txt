WEATHERPARSE BACKUP GUIDE
=========================

A backup script is included in cron/backup. It runs automatically in the Docker container; local installs need to
enable it manually.

Docker Containers
=================

The backup task is enabled in the container by default. Set BACKUPS_ENABLED=0 in the container environment to
disable it. See docs/DOCKER.txt, section "Backup/Restore".

Local Install
=============

Backup
------

- Copy the backup script to your home directory:

      cp /opt/weatherparse/cron/backup ~/

- Set MYSQL_USER, MYSQL_PASSWORD, MYSQL_HOSTNAME and MYSQL_DATABASE at the top of the script (MYSQL_DATABASE defaults
  to weatherparse; installs upgraded from Acuparse usually use acuparse). The script passes the password through
  MYSQL_PWD, so it does not show in the process list.
- Optionally edit KEEP_BACKUPS_FOR and BACKUP_CAM_IMAGES.
- Add the backup script to root's cron, for example daily at 00:05:

      crontab -l | { cat; echo "5 0 * * * /bin/bash ~/backup"; } | crontab -

Restore
-------

Extract the backup archive:

    tar -xvf /var/opt/weatherparse/backups/<BACKUPDATE>.tar.gz

Then restore your database (use your own database name):

    mariadb weatherparse < mysql.sql

Copy your config file back:

    cp config.php /opt/weatherparse/src/usr/config.php

Off-Box Copies
--------------

A backup on the same SD card or disk does not protect you from losing that card. Copy the backup files to another
machine, and check that you can read them (for example gzip -t on the archive) before you rely on them.

Updates
-------

The copy of the script in your home directory is not updated automatically. Update it by hand when the changelog
mentions changes to cron/backup.
