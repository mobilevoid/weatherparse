WEATHERPARSE DOCKER GUIDE
=========================

The WeatherParse container holds the application, Apache with PHP 8.4, cron and the camera tools. The database runs
in a second container (MariaDB). compose.yaml in this repository starts both.

Quick Start with Docker Compose
===============================

Install Docker with the compose plugin (https://docs.docker.com/get-docker/), then:

    git clone https://github.com/mobilevoid/weatherparse.git
    cd weatherparse
    cp .env.example .env
    (edit .env: set MYSQL_PASSWORD, MYSQL_ROOT_PASSWORD and TZ)
    docker compose up -d --build

Open http://<docker host>/ and finish setup in the web installer. The database host is db; the database name, user
and password are the ones in .env.

compose.yaml keeps the database, your settings, the camera pictures and the backups on named volumes (db, config, cam,
backups), so they survive "docker compose down" and image updates. "docker compose down -v" deletes them.

To update: git pull, then docker compose up -d --build, then sign in as admin; the site runs the updater if the
version changed.

Settings in .env
----------------

- TZ                    Time zone, for example America/Chicago (required by the container)
- MYSQL_DATABASE        Database name (default weatherparse)
- MYSQL_USER            Database user (default weatherparse)
- MYSQL_PASSWORD        Database user password (required)
- MYSQL_ROOT_PASSWORD   MariaDB root password (required; the container uses it once to grant the user its rights)
- HTTP_PORT, HTTPS_PORT Host ports (default 80 and 443; the AcuRite Access always sends to 443)
- WEATHERPARSE_IMAGE    Image name to build or use (default weatherparse:local)

Never commit .env; it is in .gitignore.

Passwords and Secrets
---------------------

The container keeps passwords out of world-readable files:

- The cron jobs read their database settings from /etc/weatherparse/cron.env (mode 600, root only, folder mode 700),
  written at every start. /etc/environment holds only TZ.
- MYSQL_ROOT_PASSWORD is used once at startup to grant the WeatherParse user its rights, then removed from the
  environment before Apache, cron and the health check start. It is never written to a file in the container.
- Database commands get passwords through MYSQL_PWD, not on the command line.
- The admin "config" API page shows the environment with password, secret, key and token values hidden.

Docker secrets (or any file) can replace the variables: set MYSQL_PASSWORD_FILE and/or MYSQL_ROOT_PASSWORD_FILE to
the path of a file holding the password (for example /run/secrets/weatherparse_db) instead of MYSQL_PASSWORD and
MYSQL_ROOT_PASSWORD. Setting both forms of one variable stops the container with an error. Keep such files mode 600
on the host. With MYSQL_PASSWORD_FILE, run ". /etc/weatherparse/cron.env" in a container shell before running
cron/backup by hand.

Prebuilt Images
===============

GitHub Actions builds the image for amd64 (PCs) and arm64 (Raspberry Pi 4/5) on release tags and on demand, after a
smoke test that starts compose.yaml and loads the setup page. Images go to the repository's own package
(ghcr.io/mobilevoid/weatherparse), which is private while the repository is private. To use one, set
WEATHERPARSE_IMAGE in .env (for example ghcr.io/mobilevoid/weatherparse:latest), sign in to ghcr.io if the package is
private, and run docker compose up -d without --build.

Building the Image Without Compose
==================================

    docker build -t weatherparse:local .

The container starts with the command weatherparse (see .docker/docker-entrypoint) and expects these environment
variables, at the very least: MYSQL_HOSTNAME, MYSQL_DATABASE, MYSQL_USER, MYSQL_PASSWORD, MYSQL_ROOT_PASSWORD and TZ.
Read .docker/docker-entrypoint for the full list and their defaults.

SSL Certificates
================

The container includes a self-signed (snake oil) certificate that is fine for most uses, including the AcuRite Access.
Let's Encrypt can be enabled with the LE_ environment variables read by .docker/docker-entrypoint.

Ports
=====

The container listens on ports 80 and 443. The AcuRite Access needs to send data to port 443 and this cannot be
changed. If you run several web containers on one host, put a load balancer or reverse proxy in front
(https://docs.nginx.com/nginx/admin-guide/load-balancer/http-load-balancer).

Volumes
=======

You must keep your SQL database on a volume, or it will be lost when the container is recreated. Also keep these
paths on volumes or bind mounts (https://docs.docker.com/storage/bind-mounts):

- /opt/weatherparse/src/usr: your configuration
- /opt/weatherparse/src/pub/img/cam: webcam images
- /var/opt/weatherparse/backups: config and database backups (the backup task clears old files here; do not store
  other files in it)

Webcam
======

The image includes ffmpeg, ImageMagick and the camera scripts, and cron runs them once a camera is set up. Copy
cam/templates/config.env to /opt/weatherparse/cam/config.env in the container (or bind mount your own) and set the
camera address there. Pictures are written to the cam volume.

Email
=====

For outbound email, Mailgun (https://www.mailgun.com/) is the simplest option. The image also supports Nullmailer
(https://wiki.debian.org/nullmailer) for a custom SMTP server, configured with the SMTP_RELAY and SMTP_HOST environment
variables read by .docker/docker-entrypoint.

Backup/Restore
==============

The backup script (cron/backup) runs once a day in the container and makes an incremental snapshot in
/var/opt/weatherparse/backups (map a volume there to keep it). Each snapshot is a dated folder with a database dump
and the settings and camera pictures; unchanged files are hard links to the previous snapshot. See
docs/other/BACKUPS.txt.

KEEP_BACKUPS_FOR sets how many snapshots to keep (7 by default). BACKUP_CAM_IMAGES=0 leaves out the pictures.
BACKUPS_ENABLED=0 turns backups off.

Restore
-------

Open a shell in the container and run:

    /opt/weatherparse/cron/backup list
    /opt/weatherparse/cron/backup restore                  # the newest snapshot
    /opt/weatherparse/cron/backup restore 2026-10-25_0005  # or a named one

Realtime (RTL)
==============

Realtime updates use the RTL Relay, a separate project from Acuparse (acuparse/rtl-relay). See docs/REALTIME.txt.
