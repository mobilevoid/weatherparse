WEATHERPARSE DOCKER GUIDE
=========================

Note:
    WeatherParse does not publish Docker images yet, and the Acuparse Docker images and installer scripts do not apply
    to WeatherParse. Build the image locally from the Dockerfile in this repository. The supported install method is
    the manual install in docs/INSTALL.txt.

The WeatherParse container includes the application and web server. It does NOT include a database; run MariaDB
separately (for example as a second container) and give the WeatherParse container access to it.

Building the Image
==================

Install Docker (https://docs.docker.com/get-docker/), then from a checkout of this repository:

    git clone https://github.com/mobilevoid/weatherparse.git
    cd weatherparse
    docker build -t weatherparse:local .

The container starts with the command weatherparse (see .docker/docker-entrypoint) and expects these environment
variables, at the very least: MYSQL_HOSTNAME, MYSQL_DATABASE, MYSQL_USER, MYSQL_PASSWORD, MYSQL_ROOT_PASSWORD and TZ.
Read .docker/docker-entrypoint for the full list and their defaults.

SSL Certificates
================

The container includes a self-signed (snake oil) certificate that is fine for most uses, including the AcuRite Access.
Let's Encrypt can be enabled with the LE_ environment variables read by .docker/docker-entrypoint.

Ports
=====

The container listens on ports 80 and 443. The AcuRite Access needs to send data to port 443 and this cannot be
changed. If you run several web containers on one host, put a load balancer or reverse proxy in front
(https://docs.nginx.com/nginx/admin-guide/load-balancer/http-load-balancer).

Volumes
=======

You must keep your SQL database on a volume, or it will be lost when the container is recreated. Also keep these
paths on volumes or bind mounts (https://docs.docker.com/storage/bind-mounts):

- /opt/weatherparse/src/usr: your configuration
- /opt/weatherparse/src/pub/img/cam: webcam images
- /var/opt/weatherparse/backups: config and database backups (the backup task clears old files here; do not store
  other files in it)

Webcam
======

The container is not set up to run the webcam script or to be reached over SSH. Run the webcam script on the Docker
host (copy the cam folder from this repository), and copy the images into the webcam volume. Set the paths in
cam/config.env accordingly.

Email
=====

For outbound email, Mailgun (https://www.mailgun.com/) is the simplest option. The image also supports Nullmailer
(https://wiki.debian.org/nullmailer) for a custom SMTP server, configured with the SMTP_RELAY and SMTP_HOST environment
variables read by .docker/docker-entrypoint.

Backup/Restore
==============

The backup script (cron/backup) runs once a day in the container and saves backups to /var/opt/weatherparse/backups.

Backup files are kept for 7 days by default; change this with KEEP_BACKUPS_FOR. Disable backups with BACKUPS_ENABLED=0.

Restore Database
----------------

Open a shell in the container and extract the archive:

    tar -xvf /var/opt/weatherparse/backups/<BACKUPDATE>.tar.gz

Then restore the database (MYSQL_PWD keeps the password off the command line):

    MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -h"$MYSQL_HOSTNAME" "$MYSQL_DATABASE" < mysql.sql

Restore Config File
-------------------

Extract the archive as above, then copy your config file back:

    cp config.php /opt/weatherparse/src/usr/config.php

Realtime (RTL)
==============

Realtime updates use the RTL Relay, a separate project from Acuparse (acuparse/rtl-relay). See docs/REALTIME.txt.
